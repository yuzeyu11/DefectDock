# 网络请求限流

网络模式在认证、请求大小与审计基线之上启用进程级令牌桶。本地模式保持不限流。
这是单 worker 工作站的入口防护，不是多用户配额或分布式限流服务。

## 配置

| 环境变量 | 默认额度 | 适用请求 |
| --- | --- | --- |
| `DEFECTDOCK_REQUESTS_PER_MINUTE` | 120 | 已认证、非公开的 HTTP 请求 |
| `DEFECTDOCK_MUTATIONS_PER_MINUTE` | 30 | 上述请求中的 POST、PUT、PATCH、DELETE |
| `DEFECTDOCK_AUTH_FAILURES_PER_MINUTE` | 20 | 非公开接口的鉴权失败请求 |

每个桶初始装满，最大容量就是配置额度，并以相同额度每分钟持续补充。
例如总请求额度 120 对应最多 120 次初始突发、每秒补回 2 个令牌，**不是严格的滚动窗口计数**。
所有配置必须为 1 到 1,000,000 的整数；非法值会阻止服务启动，不会静默关闭保护。
Compose 同样支持这三个变量。

写操作须同时取得总请求和写操作令牌；任何一个桶不足都拒绝，并且不扣除其他桶的令牌。
被限流请求不会进入业务处理器，也不会读取上传请求体。合法凭据不占鉴权失败额度，
因此攻击者耗尽鉴权失败桶后，合法请求仍能使用其正常额度。

## 响应与恢复

超限响应为 HTTP `429`，包含：

- `Retry-After`：再次获得令牌至少需要等待的整秒数；其他请求仍可能竞争此额度。
- `X-Request-ID`：关联审计记录。
- `Cache-Control: no-store`：避免缓存拒绝响应。
- JSON：`code: rate_limited` 和 `retry_after_seconds`。

工作台显示等待时间。用户应等待后再操作；客户端**不自动重放写请求**，避免重复训练、
导出或上传。接口轮询仍按原有周期运行，它们属于只读请求。
限流事件写入 `.defectdock/audit.jsonl`，不记录请求体、Authorization 或完整 Token。

`/`、`/api/health`、API 文档与 OpenAPI 保持公开且不消耗额度，便于运维探针与诊断。
公网部署应在可信反向代理处另外限制这些公开入口、连接数及请求体传输速度。

## 部署边界

- 额度由**整个服务进程共享**，不是按 IP、用户或 URL 分桶。多个工作台会竞争同一额度，
  可以按实际数量调整；更换 URL 或伪造 `X-Forwarded-For` 不会获得新额度。
- 桶数量固定，不保存客户端或路径字典，避免恶意身份或 URL 造成内存持续增长。
- 限流器线程安全，使用单调时钟；进程重启后额度重置。
- 每个 worker/实例有独立额度。当前保持单 worker；多实例交付应使用网关或共享存储
  提供统一限流，不应把本实现当成全局配额。
- 入口限流不等于任务并发限制、磁盘配额或防 DDoS，也不代替 TLS、真实用户身份和 RBAC。
